NWarp Default Page

It works!

This is the default welcome page used to confirm that NWarp is installed and running correctly. It is served the same way an Apache or Nginx default page would be: it shows the moment your web server process is up and serving requests, before any of your own site content is in place.

If you can read this page, NWarp has been installed and is working properly. You should replace this file (located at /var/www/nwarp-default/index.html, or www/index.html for a manual/dev build) before continuing to operate your HTTP server.

If you are a normal user of this website and don't know what this page is about, this probably means the site is currently unavailable due to maintenance. If the problem persists, please contact the site's administrator.

Configuration Overview

NWarp's configuration is a single flat key = value file, not split across multiple included files the way Apache's default layout is. The full reference is documented in README.md and docs/ARCHITECTURE.md on the project's GitHub repository.

The configuration layout for a system-wide NWarp installation is as follows:

/etc/nwarp/ |-- nwarp.conf <- main config file (host, port, TLS, proxy, WASM) |-- wasm/ <- WASM request handler modules |-- certs/ <- TLS certificate and key (if HTTPS enabled) /var/www/nwarp-default/ <- default document root (this page lives here) /var/log/nwarp/ <- access.log and error.log (structured JSON)
  • proxy_route and wasm_route entries in nwarp.conf hot-reload automatically within a few seconds of saving the file - no restart required.
  • Changes to host, port, tls_*, or worker_threads require a restart to take effect: sudo systemctl restart nwarp
  • The binary is called nwarpd and is managed using systemd, so it can be stopped, started, and restarted using systemctl. Use systemctl status nwarp to check whether the service is currently running, and systemctl enable nwarp to start it on boot.
  • Calling nwarpd directly (not through systemd) will use whichever config file is passed via --config, defaulting to ./configs/nwarp.conf if none is given.
Document Roots

By default, NWarp serves files from /var/www/nwarp-default/. To serve your own site, either replace the contents of that directory or point document_root in nwarp.conf at a different folder, then restart NWarp.

Requests matching a configured proxy_route or wasm_route prefix are not served from the document root at all - they are forwarded to an upstream server or a sandboxed WASM handler instead, before static file resolution is ever attempted.
